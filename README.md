# 하온이의 숫자놀이

4살 아이를 위한 집에서 쓰는 숫자 놀이 앱. 형제 앱 「하온이의 한글나라」(`Desktop/todo`)와 같은 화면 틀·목소리·로그인을 쓰고, **로그인 계정과 아이 정보·설정은 한글나라에서 받아온다**(같은 MongoDB, 한글나라 DB 는 읽기만).
과정은 업체(토도수학) 나이대별 과정의 학습 목표 순서를 따른다 — 레벨 A(유아) A1~A10 → 레벨 B(유치원 기초) B1~B10, 20장 × 5일 = 100일. 그림은 넘버블럭스 친구들(집에서만 쓰는 앱, `refs/` 인물구성도 기준).

## 실행

```bash
npm install
npm run dev          # http://localhost:6300
npm test             # 과정표·판 만들기·진도·스케줄·한글나라 값·로그인 검사
npm run voice:lines  # 들려줄 말 목록 → scripts/voice-lines.json
npm run voice:reuse  # 한글나라에 이미 구운 같은 말 빌려 오기 (크레딧 안 씀)
npm run voice:make -- --voice sua          # 남은 말 견적만 (--yes 를 붙이면 굽는다 · 안전선 19만 자에서 멈춤)
npm run voice:timing # 구운 음성마다 말소리 구간 → src/content/voice-timing.json (노래방 읽기)
npm run image:list   # 힉스필드로 만들 그림 목록 → scripts/image-list.json
npm run image:prompts                     # 그림마다 프롬프트·레퍼런스 → scripts/image-prompts.json
npm run image:install -- drafts/<날짜>     # 힉스필드 결과(results.json) 내려받기 → public/img WebP + image-manifest(?v=내용 해시)
npm run image:upload                      # public/img → 회사 Cafe24 /app/img/lsh/num/
```

`.env.example` 을 `.env.local` 로 복사해 채운다 — 값은 한글나라와 같고 `MONGO_DB=haonnumber` · `HANGUL_DB=todohangul` · `CAFE24_UPLOAD_DIR=/app/img/lsh/num/` 만 다르다.
Vercel 환경변수: `MONGODB_URI` · `MONGO_DB` · `HANGUL_DB` · `ACCOUNTS` · `AUTH_SECRET` · `CAFE24_PUBLIC_BASE_URL` · `CAFE24_UPLOAD_DIR` (그림 주소는 빌드 때 정해지니 값을 넣고 다시 배포).

## 한글나라에서 받아오는 것 (2026-10-27 사용자 결정 — 같은 MongoDB 직접)

| 무엇 | 어디서 | 숫자놀이에서 |
|---|---|---|
| 로그인 계정 | `ACCOUNTS`(같은 값) + 한글나라 DB `users` | 같은 아이디·비밀번호로 들어온다. 계정 만들기·비밀번호는 한글나라 관리자 페이지에서 |
| 화면 방향 · 공부하는 요일 · 성우 | 한글나라 DB `progress.<아이디>.settings` | 그대로 따른다(바꾸는 곳은 한글나라 부모 페이지). 기기에 받아 두고 켤 때마다 새로 받는다 — `lib/family` |
| 아이 이름 · 얼굴 | `curriculum/child.ts`(이하온·하온아·하온이) · 한글나라 Cafe24 `child:face` | 같은 파일·같은 그림 주소 |
| 한글나라 시작한 날 | `settings.startOn` 또는 `progress.firstOn` | 부모 페이지에 보여 주기만 — 숫자놀이 '온 지 며칠째'는 숫자놀이를 처음 한 날부터 |

숫자놀이 진도는 **다른 DB**(`MONGO_DB`, 기본 `haonnumber`)의 `progress` 에 쓴다. 두 DB 이름이 같으면 한글나라 진도를 덮어쓸 수 있어서 서버가 멈춘다(`lib/db.ts`).

## 과정 — 업체 레벨 A·B 학습 목표 순서 (`src/curriculum/course.ts`)

2026-10-27 사용자: "해당 업체에서 진행하는 나이대별 커리큘럼을 따라서". 목표·순서는 업체 공개 교사용 페이지(todoclassroom.com/todomath/curri — `docs/HANDOFF.md` 4절), 나이는 앱스토어 설명(A 유아 · B 유치원 기초 · C 유치원 발전 · D·E 1학년). **장 하나 = 학습 목표 하나**, 5일째 도장 놀이가 업체의 형성 평가 자리. 놀이·화면·캐릭터는 우리 것(업체 스테이지의 실제 활동은 공개돼 있지 않고, 앱을 그대로 옮기지 않는다).

| 장 | 목표 | 제목 | 주된 놀이 |
|---|---|---|---|
| 1 | A1 | 다섯까지 세기 | 숫자 친구 1~5 만나기 · 하나씩 세기 |
| 2 | A2 | 모양 이름 | 모양 찾기(같은 색·크기의 반듯한 모양) |
| 3 | A3 | 수만큼 나타내기 (1~5) | 블록 쌓기 · 짝짝 손뼉 |
| 4 | A4 | 수와 양 (1~5) | 몇 개일까 · 더 많은 쪽 |
| 5 | A5 | 모양 알아보기 | 모양 찾기(크기·색·방향이 달라도) |
| 6 | A6 | AB 규칙 | 규칙 찾기 AB |
| 7 | A7 | 열까지 세기 | 숫자 친구 6~10 만나기 · 하나씩 세기 |
| 8 | A8 | 수만큼 나타내기 (6~10) | 블록 쌓기 · 짝짝 손뼉 |
| 9 | A9 | 크기 비교 | **크기 비교**(새 놀이) |
| 10 | A10 | 수와 양 (6~10) | 몇 개일까 · 더 많은 쪽 |
| 11 | B1 | 스물까지 세기 | 숫자 친구 11~20 만나기 · 하나씩 세기 |
| 12 | B2 | 스물까지 차례 | 다음 숫자 · 숫자 찾기 |
| 13 | B3 | ABC 규칙 | 규칙 찾기 ABC(+AAB) |
| 14 | B4 | 모으기 (5까지) | 모아 보기(숫자 친구 둘 "3 하고 1 → ?" — 기호 대신 하고·화살표. 맞히면 두 친구 블록이 한 기둥으로 합쳐져 답 친구로, 더하기와 같은 장면 `FriendSum`) |
| 15 | B5 | 더하기 (5까지) | **더하기**(새 놀이, 3 + 2 = ? — 숫자마다 위에 숫자 친구, 보기 카드도 숫자 옆에 친구. 맞히면 두 친구가 답 자리로 뛰어들어 제 색 블록 기둥으로 합쳐졌다가 답 친구로 변신) |
| 16 | B6 | 수와 양 (11~20) | 몇 개일까 11~20 |
| 17 | B7 | 빼기 (5까지) | **빼기**(새 놀이, 5 − 2 = ? — 떠나는 친구는 흐리게 둥실. 맞히면 앞 친구가 블록 기둥이 되고 위 블록이 날아간 뒤 남은 기둥이 답 친구로) |
| 18 | B8 | 수만큼 나타내기 (11~20) | 블록 쌓기 11~20 |
| 19 | B9 | 모양 나누기 | **모양 나누기**(새 놀이, 색·크기로 골라 모으기) |
| 20 | B10 | 수 크기 비교 (10까지) | 더 많은 쪽 — 숫자로("어느 수가 더 클까?") |

- 하루 = 그 장 목표 놀이 1~2개 + 앞에서 배운 것 되풀이(업체 원칙: 같은 개념을 여러 놀이로 반복), 놀이 3~4개(10분쯤), 하루 한 번(부모가 '한 판 더' 열 수 있음, 마스터는 제한 없음)
- 5일째 = **도장 놀이**(점수 놀이만, 첫 시도 80% 이상이면 도장) → 못 받으면 연습 놀이 하루 → 도장 놀이 한 번 더 → 그래도 못 받으면 다음 장(부모 페이지 '다시 볼 장')
- 다음에 넓힌다면 레벨 C(유치원 발전): 10 이하 덧뺄셈·10 만들기·10씩 뛰어 세기·시계 정각·십과 낱개(`docs/HANDOFF.md` C1~C10)
- 보상 = **블록**(놀이 1 + 하루 끝 3 + 도장 5, 놀이터는 놀이마다 하루 첫 판 1). 숫자 친구는 만나는 날을 끝내면 「숫자 친구」 앨범에
- 숫자 읽기(2026-10-27 사용자): 숫자 친구 이름은 공식 한국어판·카드처럼 "일·이·삼", 셀 때·몇 개·숫자 찾기는 "하나·둘·셋", 만나기에서 "삼! 셋이라고도 해." — `curriculum/numbers.ts`
- 친구마다 성격 소개 한 줄(카드 소개 `refs/card-intro` 를 4살 눈높이로 줄임) — 만나기·친구 앨범에서 인사 다음에

## 놀이 16가지 (`src/components/play/activities`)

숫자 친구 만나기 · 하나씩 세기 · 몇 개일까? · 숫자 찾기 · 블록 쌓기 · 숫자 쓰기(따라 쓰기) · 짝짝 손뼉 · 더 많은 쪽(물건·숫자) · 다음 숫자 · 모양 찾기 · 규칙 찾기 · 모아 보기 · 크기 비교(A9) · 더하기(B5) · 빼기(B7) · 모양 나누기(B9).
새 놀이 넷도 놀이터에 있다(과정에서 처음 나온 날부터 열림, 2026-10-27 카드 장면 생성). 놀이 아이콘은 `icon:play:<놀이>`(오늘의 놀이 순서 표시·놀이터 제목) — 같은 뜻 그림이 이미 있는 놀이(만나기·몇 개일까·블록 쌓기·숫자 쓰기·손뼉)는 그 그림(`lib/assets` UI_ART).
보기를 누르면 이름("셋")을 먼저 읽고 딩동댕/땡, 정답은 칭찬을 끝까지 듣고 넘어간다(한글나라 `lib/answer` 그대로). 문제는 시작할 때 섞는다(`lib/rounds.ts`, 순수 함수 + 테스트).

## 숫자 놀이 — 오리지널 게임 (`src/components/games`, 2026-10-27 사용자: "너랑 나랑 만든 오리지널 숫자 게임")

놀이 방식은 우리가 정했다 — 토도수학 자유 모드·사고력 게임이나 넘버블럭스 공식 앱 게임을 옮기지 않는다. 판 만들기·규칙은 순수 함수(`lib/originals.ts`, `lib/yut.ts`) + 테스트.

| 게임 | 하는 법 | 익히는 것 |
|---|---|---|
| 주사위 윷놀이 | 몇 명이서(둘이·셋이 — 혼자는 상대가 없어 뺐다) → **컴퓨터랑**(스스로 굴림) 또는 **친구랑**(사람이 직접 — 이름: 엄마·아빠·언니·오빠·누나·형·할머니·할아버지 또는 직접 쓰기) → 저마다 숫자 친구 고르기(십까지). 「주사위 굴리기」→ 큰 주사위가 하늘에서 쿵 떨어져 도로로로 구르다 멈추고 나온 수를 크게("6 여섯!"). 반짝이는 칸을 하나씩 누르며 "한 칸, 두 칸". 윷판 그대로 모서리·가운데에 딱 멈추면 지름길, 다른 말 칸에 멈추면 잡기(그 말은 처음부터 다시 출발, 잡은 쪽은 한 번 더), 6 도 한 번 더 | 주사위 눈 · 한 칸씩 세기 · 차례 |
| 블록 친구 만들기 | 예시 친구가 인사하고, 그 친구 모양 빈 틀(4는 2×2, 9는 3×3, 7은 기둥)을 아래 상자의 **일(1)** 로 채우기 — 일은 남은 칸 수만큼, 칸막이 너머 **이·삼 묶음**은 한꺼번에 두·세 칸(남은 칸보다 크면 흐림), 이어 세기("셋, 넷"). 넣은 블록은 들어온 친구 색(일 빨강·이 주황·삼 노랑)으로 쌓이고, 다 차면 그 친구 색으로 바뀌며 변신(친구 넷, 십까지) | 모든 수는 일이 모여서 · 모으기 · 모양 |
| 그림자 친구 | 그림자는 가만히, 옆의 친구를 끌어다 그림자 위에 놓기(실루엣은 `scripts/image-shadows.mts` — 친구 그림의 모양만, 머리 위 숫자 지움) | 모양으로 수 알아보기 |
| 시소 | "구와 십 중에 어느 쪽이 더 무거울까?" → 기울고 "십이 블록이 더 많아서 내려갔어!" · 오른쪽에 블록을 넣어 똑같게 | 더 큰 수 · 같은 수 |
| 간식 나누기 | 쿠키를 끌어서 친구에게 가져다주기(접시끼리 옮기기·도로 가져오기), 다 나누면 "둘씩 똑같아!" | 똑같이 나누기 |
| 북소리 세기 | 일이 친 북소리를 듣고 숫자 고르기(여섯까지), 「다시 듣기」 | 소리로 세기 |

## 그림 — 넘버블록스 (`refs/`, 저장소에 올리지 않음)

82장 모두 힉스필드에서 만들어 Cafe24 에 올렸다(2026-10-27) — 친구 대표 20 · 기둥 4 · 안내 친구 3 · 앱 아이콘 · 물건 12 · 메뉴·UI 아이콘 12 · 놀이 아이콘 11 · 놀이터 장면 14 · 바탕 5. 그림이 없는 키는 임시 그림(흰 블록·숫자 카드·이모지)으로 보인다. 캐릭터를 직접 흉내 내 그리지 않는다 — refs 를 레퍼런스로 힉스필드에서 만든다.
- 그림체 조사(공식·팬 자료 + refs 확대 관찰, 출처 포함): [docs/numberblocks-style.md](docs/numberblocks-style.md) → 프롬프트 문구 `scripts/image-style.mts`, 친구 생김새 `src/curriculum/friends.ts`
- 숫자 친구 모습 두 가지(2026-10-27 사용자): **대표 모습 = 인물구성도**(4는 2×2, 6은 2×3, 8은 2×4, 9는 3×3) `friend:<n>`, **기둥 모습 = 인물구성2** `friend:<n>:tower`(4·6·8·9) — 블록 쌓기 정답·숫자 친구 「변신!」에 쓴다
- 생성용 레퍼런스는 로고·남의 워터마크를 지운 사본 `refs/gen/`(`node scripts/refs-clean.mts`) — 원본은 그대로. 11~20 은 카드 소개(`refs/card-intro`) 속 캐릭터를 잘라 `refs/gen/card/<n>.png` 로
- 생성기는 긴 몸(8·9·10 기둥, 11, 20)의 블록을 1~2개 적게 그리곤 한다 → 다시 뽑지 않고 `scripts/image-seams.mts` 로 그 그림 속 블록 한 줄을 복사해 끼운다(결과 원본은 `drafts/<날짜>/png/`, results.json 에 `local:fixed` 로 적어 둠). 설치 전 블록 수를 꼭 센다
- GPT Image 2.5 medium(1k 투명 0.5 · 2k 바탕은 견적보다 비쌌다). 힉스필드는 회사 계정 — 생성은 장수·크레딧을 먼저 말하고 확인받은 뒤, 끝나면 바로 내려받고 "지워도 돼요"라고 알린다
- 공식 로고는 앱 화면에 넣지 않는다(상표). 정식 한국어 표기는 「넘버블록스」. 친구 이름은 공식 한국어판처럼 한자어(일·이·삼, 2026-10-27 사용자)

## 목소리

수아(Typecast) 268줄(1~20 이름·성격 소개, 새 놀이 41줄 포함) — 한글나라에서 같은 말을 빌려 오고(`voice:reuse`) 나머지는 2026-10-27 구움. 보이스동화 안전선이 19만 8천(10-26 사장님 요청)이라 그 선으로 구웠다(`TYPECAST_SAFE_LIMIT=198000`, 이번 달 약 19.28만 — 기본 안전선 19만으로 견적을 내면 '넘어요'가 뜨지만 구울 줄이 0이면 괜찮다).
말을 고치면 `voice:lines → voice:reuse → voice:make -- --voice sua → voice:prune(안 쓰는 옛 음성 정리) → voice:timing`.

## 화면 시험

`docs/tools/test/` 의 캡처·잘림 점검 스크립트(포트 6300, fe 로그인). **`/api/progress` 는 Fetch 로 막고** 찍는다 — 안 막으면 fe 의 실제 기록이 바뀐다.

- 놀이 화면 하나만 볼 때는 미리 보기 주소 `/play?preview=c12d4&step=2&auto=1`(12장 4일 세 번째 놀이) — 진도에 남지 않고 판이 고정된다
- 블록 쌓기·짝짝 손뼉처럼 하면서 늘어나는 화면은 첫 화면만으로는 모른다 — 끝까지 채워 보고 「다 됐어!」가 화면 안인지 본다(2026-10-27 블록이 다섯 줄 차면 가로 화면 버튼이 밀려서, 가로에선 숫자를 쌓는 곳 왼쪽에 두고 블록을 8vh 로. 세로에서 열하나 이상을 맞히면 친구가 블록 위에 겹쳐 나온다)
- 하루 끝 화면도 새 친구가 있는 날은 길다 — 폰 가로(높이 520 이하, `short:`)는 두 칸(왼쪽 축하 · 오른쪽 새 친구·집으로)
